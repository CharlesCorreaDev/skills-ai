OWA is an event-based framework composed of a variety of event handlers that are designed to perform specific analytic/logging functions. Events are composed of an event type and a message. An event's message could be an array, object, or any other data type.

## Tracking Events

The following events are fired when certain actions relating to tracking occur. Event handlers can listen for these events and perform their own actions.

| Event Name | Description |
| --- | --- |
| `base.first_page_request` | Fired when a new visitor views a page. |
| `base.page_request` | Fired when a page view occurs. |
| `base.page_request_logged` | Fired after a request event has been written to the database. |
| `base.new_session` | Fired whenever a new session is logged to the database. |
| `base.session_update` | Fired when an existing session has been updated. |
| `base.feed_request` | Fired whenever there is a request for an RSS/ATOM/XML feed. |
| `dom.click` | Fired when a DOM click event is generated by a browser. |
| `dom.stream` | Fired when a DOM stream is recorded. |

## General Actions

| Event Name | Description | Properties |
| --- | --- | --- |
| `init` | Fired after OWA has loaded its configuration and modules but before the most global framework objects have been set up. |  |

The event a tracking request is finally processed into is passed through the
`post_processed_tracking_event` **filter** rather than announced as an event —
see [Filters](Filters.md).

## Handling Events

Module developers can write [Event Handlers](Event-Handlers.md) that can be configured to listen for one or more event types.
