This page contains information pertaining the development of OWA.

## Testing

OWA has PHP (PHPUnit), JavaScript (Jest), and end-to-end (Playwright) test suites, plus static analysis and lint, all wired into GitHub Actions CI. See the [Testing](Testing.md) page for what each suite covers, how to run them manually, and how they run in CI.

## PHP

All third party PHP dependancies are managed via Composer.

### Composer

Each module can specify its dependancies graph in its own `composer.json` file. The composer.json file for each module is automatically merged to create a single top level dependency graph.

- To install php dependancies run the following from the top level:

`composer install`

- To update php dependancies run:

`composer update`

## Javascript

JavaScript builds are managed using npm/webpack and all new Javascript code should be written using ES6 style modules.

### npm

Node Package Manager (npm) is used to manage OWA's Javascript dependancies and builds.The npm configuration is stored in `package.json`.

- To install the necessary node modules for the project:

`npm install`

- To run a development build with live watching of files:

`npm start`

- To run a production build:

`npm run build`

### Webpack

We use Webpack 5 for **all** asset bundling — JavaScript **and** CSS. The configuration is stored in `webpack.config.js`.

> **The old `cmd=build` CLI pipeline has been retired.** Earlier versions built the combined reporting stylesheet (and registered build packages) through a PHP command, `php cli.php cmd=build`. That command, the `owa_buildController`, and the per-module build-package API have all been removed. **`npm run build` is now the single way to build every asset**, including the combined CSS.

#### Per-module build manifests

Build products are no longer hard-coded in `webpack.config.js`. Instead, each module declares what it builds in a **`build.manifest.json`** file at the module root (e.g. `modules/Base/build.manifest.json`), and `webpack.config.js` discovers these manifests and turns each declared package into a webpack build. This is the build-side analogue of how each module's `composer.json` is merged into one dependency graph.

Each package entry declares its own `outputDir` (relative to the module directory). For example, `modules/Base/build.manifest.json` declares three packages:

- **`owa.tracker.js`** (`type: js`) — the tracker, built from `src/tracker/tracker-dom.js`, with its npm vendor code split into `owa.vendors.js`. Output: `public/base/dist`.
- **`owa.reporting-combined-min.js`** (`type: js`) — the reporting bundle, built from `src/reporting/v1/reporting-entry.js`. Output: `public/base/dist`.
- **`owa.reporting-css-combined.css`** (`type: css`) — the combined reporting stylesheet, built from the six source CSS files, which also copies the url()-referenced images/fonts into `public/` alongside it. Output: `public/base/css`.

#### Src & Dist Paths

- JavaScript **and CSS source files** are stored under `modules/Base/src` and `modules/Base/css`.
- Webpack emits packaged bundles into the web-facing `public/` tree (each package's `outputDir` is declared in its module's `build.manifest.json`). **NOTE:** The `public/` directory contains build artifacts and should never be checked into Git — it is regenerated by `npm run build` (and is included, pre-built, in the packaged release tarball).

**--> *IMPORTANT NOTE* about the JS tracker location!!!**

The JS tracker is now served from `public/base/dist/owa.tracker.js`. The old locations (`modules/base/dist/owa.tracker.js` and the older `js/owa.tracker-combined-min.js`) are no longer written; requests to them are handled by a 301 redirect to the new path so existing tracker tags keep working.

#### Bundles

The current bundles are:

- **owa.tracker.js**: an ES6 version of the entire tracker code base. Source files are in `src/tracker`.
- **owa.vendors.js**: the npm-managed vendor files imported by the tracker's ES6 modules, split out of the tracker bundle.
- **owa.heatmap.js & owa.player.js**: dynamic-import chunks separated out from the tracker bundle because they are only needed by reporting users viewing overlays.
- **owa.reporting-combined-min.js**: the reporting bundle. Source files are in `src/reporting/v1`. As of 1.9.0 these are **real ES modules** built through the webpack module graph (the old flat concatenation has been retired), running on jQuery 3.x with modernized vendor plugins. A future v2 bundle will move the reporting UI to React.
- **owa.reporting-css-combined.css**: the combined reporting stylesheet, also produced by webpack (see the manifest above).
